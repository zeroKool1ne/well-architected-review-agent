The problem

A customer asks: is my architecture sound?

Usually one artefact exists. A diagram in a slide deck.

No Terraform state. No config export. A picture.

Checking it by hand means holding 178 best practices in your head and comparing them against that picture.

Measurement 2 · the one that changed the design

Telling a model not to hallucinate does not work

“Never write that something is missing, disabled or unencrypted because the diagram is silent about it.”
— in the system prompt, verbatim

With that instruction in place, the deliberately flawless test diagram still drew findings about:

  • missing mTLS
  • a single availability zone — on a diagram that names no zone
  • absent CloudFront

Strengthening the wording made it worse.

5 findings on a diagram whose correct answer is zero.

A model that wants to be useful will find something. Instruction competes with that pull — and loses.

Trade-offs taken knowingly

  • numpy, not chromadb at runtime — 82 MB of ONNX runtime for an embedding model never called. Identical results, verified.
  • zip, not a container — 60 MB fits, no registry, no image pull.
  • Three pillars, not six — the factory scales; ground truth exists for three.

≈ $0.0005 per review · 2,000 reviews per dollar

Honestly

What is still wrong

  • The clean diagram still draws about one false positive per run.
  • Pillar attribution drifts — missing backups are sometimes filed under cost.
  • Results vary between runs despite temperature 0. Every number here is a mean for that reason.
  • Generated test diagrams all look alike; hand-drawn ones are not represented.

Next

  • Pillar attribution checked the same way findings are — structurally, not by instruction.
  • More test cases, including messy real diagrams.
  • The corrected graphs are the start of an evaluation set that grows by being used.
The gate is not a limitation to engineer away. It is where the system earns trust.
